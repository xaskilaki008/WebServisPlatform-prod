# Блок-схема алгоритма, используемого в ВКР

Алгоритм предназначен для автоматического получения прогноза волнения моря из открытых данных DWD EWAM, привязки значений прогноза к пляжам Севастополя и обновления категории состояния пляжа в информационной системе.

```mermaid
flowchart TD
    A([Начало]) --> B[Запуск фоновой загрузки DWD]
    B --> C{Загрузка уже выполняется?}
    C -- Да --> C1[Вернуть статус: загрузка уже запущена] --> Z([Конец])
    C -- Нет --> D[Установить статус running и создать блокировку]

    D --> E[Запустить команду wave:fetch]
    E --> F[Считать настройки подключения DWD]
    F --> G[Проверить каталоги запусков модели: 12 и 00]

    G --> H[Для каждого параметра swh, tm10, mwd получить индекс файлов]
    H --> I{Индексы DWD доступны?}
    I -- Нет --> I1[Записать ошибку и завершить загрузку] --> Z
    I -- Да --> J[Выбрать файлы прогноза на 0-24 часа]

    J --> K{Найден полный набор файлов?}
    K -- Нет --> K1[Записать ошибку: полный запуск модели не найден] --> Z
    K -- Да --> L[Выбрать самый новый актуальный запуск модели]

    L --> M{Утилита wgrib2 доступна?}
    M -- Нет --> M1[Записать ошибку: wgrib2 не найден] --> Z
    M -- Да --> N[Получить список пляжей из базы данных]

    N --> O{Список пляжей пуст?}
    O -- Да --> O1[Записать ошибку: нет пляжей для обработки] --> Z
    O -- Нет --> P[Перебор часов прогноза]

    P --> Q[Перебор параметров волнения: высота, период, направление]
    Q --> R[Скачать GRIB2.BZ2 файл с сервера DWD]
    R --> S{Файл скачан успешно?}
    S -- Нет --> S1[Записать предупреждение и перейти к следующему файлу] --> Q
    S -- Да --> T[Распаковать BZIP2 в GRIB2]

    T --> U{Распаковка успешна?}
    U -- Нет --> U1[Записать предупреждение и перейти к следующему файлу] --> Q
    U -- Да --> V[Сохранить временный GRIB2 файл]

    V --> W[Перебор пляжей]
    W --> X{У пляжа есть координаты для прогноза?}
    X -- Нет --> W
    X -- Да --> Y[Выполнить wgrib2 -lon для координат пляжа]

    Y --> AA{Значение извлечено?}
    AA -- Нет --> AA1[Записать предупреждение и перейти к следующему пляжу] --> W
    AA -- Да --> AB[Сохранить значение параметра во временный массив]

    AB --> W
    W --> AC{Все пляжи обработаны?}
    AC -- Нет --> W
    AC -- Да --> AD[Удалить временный GRIB2 файл]

    AD --> AE{Все параметры и часы обработаны?}
    AE -- Нет --> Q
    AE -- Да --> AF{Есть разобранные данные?}

    AF -- Нет --> AJ0[Зафиксировать завершение без сохранённых прогнозов]
    AF -- Да --> AG[Сохранить прогнозы в таблицу wave_forecasts]
    AG --> AH[Рассчитать актуальный прогноз для каждого пляжа]
    AH --> AI[Обновить wave_level в таблице beaches]
    AI --> AJ[Обновить версию кеша прогноза]

    AJ0 --> AK
    AJ --> AK[Записать статус success и снять блокировку]
    AK --> Z([Конец])
```

## Краткое описание этапов

1. Система запускает фоновую загрузку и проверяет, не выполняется ли уже другой процесс обновления.
2. Команда `wave:fetch` выбирает последний доступный запуск модели DWD EWAM из каталогов `00` и `12`.
3. Для параметров `swh`, `tm10` и `mwd` выбираются полные наборы файлов прогноза на ближайшие 24 часа.
4. Каждый файл скачивается, распаковывается из `bz2` в `grib2` и обрабатывается утилитой `wgrib2`.
5. Для каждого пляжа по координатам извлекаются значения высоты волны, периода волны и направления волны.
6. Полученные значения сохраняются в таблицу `wave_forecasts`.
7. Для каждого пляжа выбирается ближайший актуальный прогноз, после чего рассчитывается и обновляется уровень волнения `wave_level`.
8. Результат используется интерфейсом карты для отображения состояния пляжей.

## Правило расчёта уровня волнения

В текущей реализации уровень волнения определяется по высоте волны:

| Высота волны | Значение `wave_level` | Интерпретация |
|---|---:|---|
| менее 0.1 м | 0 | слабое волнение |
| 0.1-0.5 м | 2 | небольшое волнение |
| 0.5-1.25 м | 4 | умеренное волнение |
| 1.25-2.5 м | 6 | заметное волнение |
| 2.5-4.0 м | 9 | сильное волнение |
| 4.0 м и выше | 10 | очень сильное волнение |

## Основные программные элементы

- `app/Services/WaveFetchService.php` — запуск фонового процесса, статус, блокировка, журналирование.
- `app/Console/Commands/FetchDwdWaveData.php` — основной алгоритм загрузки, разбора и сохранения прогноза DWD.
- `app/Services/DwdHttpClient.php` — HTTP-клиент для DWD с повторами запросов и диагностикой подключения.
- `app/Services/WaveForecastSelector.php` — выбор актуального прогноза и обновление уровня волнения пляжа.
- `app/Models/WaveForecast.php` — расчёт `wave_level` по высоте волны.

# Блок-схема работы парсера DWD

Эта схема описывает только внутреннюю работу парсера прогноза волнения, который реализован в команде `wave:fetch`.

```mermaid
flowchart TD
    A([Начало работы парсера]) --> B[Загрузить конфигурацию DWD и путь к wgrib2]
    B --> C{wgrib2 доступен?}
    C -- Нет --> C1[Записать ошибку: утилита wgrib2 не найдена] --> Z([Завершение с ошибкой])
    C -- Да --> D[Получить список пляжей из базы данных]

    D --> E{Есть пляжи для обработки?}
    E -- Нет --> E1[Записать ошибку: список пляжей пуст] --> Z
    E -- Да --> F[Проверить каталоги модели DWD EWAM: 12 и 00]

    F --> G[Скачать HTML-индексы каталогов swh, tm10, mwd]
    G --> H{Индексы получены?}
    H -- Нет --> H1[Записать ошибку доступа к DWD] --> Z
    H -- Да --> I[Найти имена файлов GRIB2.BZ2 по шаблону EWAM]

    I --> J[Определить время запуска модели и часы прогноза]
    J --> K[Оставить прогнозы только на 0-24 часа]
    K --> L{Для часа прогноза есть swh, tm10 и mwd?}
    L -- Нет --> L1[Пропустить неполный час прогноза] --> K
    L -- Да --> M[Сформировать полный набор файлов по часам прогноза]

    M --> N{Найден хотя бы один полный набор?}
    N -- Нет --> N1[Записать ошибку: нет полного запуска модели] --> Z
    N -- Да --> O[Выбрать самый свежий запуск модели]

    O --> P[Начать перебор часов прогноза]
    P --> Q[Выбрать очередной час прогноза]
    Q --> R{Все часы обработаны?}
    R -- Да --> AH{Есть извлечённые данные?}
    R -- Нет --> S[Начать перебор параметров swh, tm10, mwd]

    S --> T[Выбрать очередной параметр]
    T --> U{Все параметры обработаны?}
    U -- Да --> Q
    U -- Нет --> V[Сформировать URL файла DWD]

    V --> W[Скачать файл GRIB2.BZ2]
    W --> X{Скачивание успешно?}
    X -- Нет --> X1[Записать предупреждение и перейти к следующему параметру] --> T
    X -- Да --> Y[Распаковать BZIP2-содержимое]

    Y --> AA{Распаковка успешна?}
    AA -- Нет --> AA1[Записать предупреждение и перейти к следующему параметру] --> T
    AA -- Да --> AB[Сохранить временный GRIB2-файл]

    AB --> AC[Начать перебор пляжей]
    AC --> AD[Выбрать очередной пляж]
    AD --> AE{Все пляжи обработаны?}
    AE -- Да --> AF[Удалить временный GRIB2-файл] --> T
    AE -- Нет --> AG{У пляжа есть координаты для прогноза?}

    AG -- Нет --> AD
    AG -- Да --> AI[Выполнить wgrib2 -lon longitude latitude]
    AI --> AJ{В ответе найдено val?}
    AJ -- Нет --> AJ1[Записать предупреждение] --> AD
    AJ -- Да --> AK[Сохранить значение во временный массив parsedData]
    AK --> AD

    AH -- Нет --> AH1[Завершить без сохранения прогнозов] --> Z2([Успешное завершение])
    AH -- Да --> AL[Сохранить parsedData в wave_forecasts]
    AL --> AM[Для каждого пляжа выбрать ближайший актуальный прогноз]
    AM --> AN[Рассчитать wave_level по высоте волны]
    AN --> AO[Обновить wave_level в таблице beaches]
    AO --> AP[Обновить версию кеша прогноза]
    AP --> Z2([Успешное завершение])
```

## Расшифровка обозначений парсера

- `swh` — значимая высота волны, сохраняется как `wave_height`.
- `tm10` — период волны, сохраняется как `wave_period`.
- `mwd` — направление волны, сохраняется как `wave_direction`.
- `GRIB2.BZ2` — сжатый файл прогноза DWD.
- `wgrib2 -lon` — команда извлечения значения из GRIB2-файла по координатам пляжа.
- `parsedData` — временный массив разобранных значений перед записью в базу данных.
